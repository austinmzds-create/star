|---|---|---|
| id | PK | |

### MaterialPost + MaterialAsset(内容帖 —— 需求3)

**MaterialAsset**:id、post_id(index)、type(`image/video/pdf/file/link`)、oss_key?、source_link?、filename?、sort_order(int)、created_at
> 旧 `Material` 表保留只读兼容,列表里继续展示。

### ConnectionRequest(建联申请 —— 需求4)
id、influencer_id(index)、requester_bd_id、current_owner_bd_id(申请时归属快照)、reason、status(`pending/approved/rejected/withdrawn`)、reviewed_by?、review_note?、created_at、reviewed_at?

### 约束变更
`Influencer.douyin_id` 规范化后**唯一**(去首尾空格 + 去前导 @)。应用层建档/合并前先查重强校验;模型加 UniqueConstraint(仅对新库生效,现有库需 Alembic/手动迁移——上线前处理)。

## 需求1 · 达人详情"产品合作"改版

**页面**:达人详情原「合作轮次」tab → 「产品合作」。每个**被分配/有业务的产品 = 一张大卡片**。原「变更记录」→「全部动态」。

**产品卡片头部统计**(全部由现有表聚合,不新建重模型):
- 产品图/名称/价格/商品ID
- 最初分配人 + 分配时间(取 AccessGrant.granted_by / granted_at 最早一条)
- 当前归属商务(influencer.owner_bd)
- 产品默认佣金 + 达人当前佣金
- 累计 GMV / 近30天 GMV(OrderRecord 按 influencer+product 求和)
- 寄样次数 / 已签收数(SampleOrder)
- 视频数 / 通过 / 未通过(VideoTask)
- 投流次数 + 状态(Promotion)
- 总操作数 + 最近动态时间(OperationLog)

**卡片展开 → 该产品时间轴**:OperationLog 按 influencer_id+product_id 倒序(分配/改佣金/寄样全流程/视频全流程/投流/GMV/催拍/备注/卡审/素材下载…)。

**接口**:
- `GET /api/influencers/{id}/collaborations` → 产品卡片数组(上面的统计字段)
- `GET /api/influencers/{id}/collaborations/{product_id}/timeline?page=` → 该产品时间轴(分页)
- `GET /api/influencers/{id}/logs?product_id=&type=&actor_id=&page=` → 「全部动态」(可按产品/类型/操作人/日期筛选)

## 需求2 · 抖音号唯一 + 重复确认 + 完整操作留痕

**规则**:抖音号规范化后作达人唯一标识;UID/手机/合作码只作辅助冲突提醒。

**录入/粘贴/Excel 统一流程**:
1. 规范化抖音号 → 查重。
2. 不存在 → 正常建档。
3. 存在 → **不新建**,返回二次确认数据:`{existing:{已有字段}, incoming:{本次字段}, diff:[{field, old, new}]}`;前端弹左右对比框,勾选要更新的字段 + 填变更原因。
4. 确认 → 按选中字段更新已有达人,**逐字段写 OperationLog**(profile_changed,detail 存 old/new,summary 如"商务张三 修改 收件地址")。

**权限**:管理员/归属商务可确认更新;非归属商务只读、走建联(见需求4)。Excel 重复行进「待处理」不自动覆盖;敏感字段(归属、管理员备注)不随导入改。

**接口**:
- `POST /api/influencers/parse`(已存在)扩展:命中重复时返回 existing/incoming/diff。
- `POST /api/influencers/{id}/apply-update` `{fields:{...}, reason}` → 应用选中字段 + 逐条落日志。
- 「全部动态」读 OperationLog(与需求1同一入口)。

## 需求3 · 素材"朋友圈内容帖"

**发布交互**:产品抽屉素材 tab 顶部「+ 发布素材」→ 弹框/抽屉:
选分类 → 拖拽/选多个文件(图/视频/附件,上传即预览) → 填标题(可改名) → 填说明文案(必填) → 允许下载开关 → 可调附件顺序 → 发布 / 存草稿。上传复用现有 `/api/upload`。

**卡片(管理端与达人端同款)**:上=标题/发布人/时间;中=图片宫格 / 视频 / 附件卡;下=完整说明文案;操作=预览、下载、复制文案;管理端额外:编辑、改名、下架(草稿/发布切换)。

**接口(管理端)**:
- `POST /api/products/{id}/material-posts` `{category,title,caption,downloadable,assets:[{type,oss_key/source_link,filename}]}`
- `PATCH /api/products/material-posts/{post_id}`(改标题/文案/下载/发布状态/附件)
- `DELETE /api/products/material-posts/{post_id}`
- `GET /api/products/{id}/material-posts`(含草稿)

**接口(H5 达人)**:
- `GET /api/h5/products/{id}/materials` 增 `material_posts`(仅 published):图片给可预览 URL,视频/附件给下载入口;下载复用现有留痕接口。

## 需求4 · 商务全库可见 + 归属控制 + 建联审批

> 说明:这**放宽了此前"商务只管自己达人"的读权限**——商务现在能看全库,但**写操作仍仅归属商务/管理员**(复用现有 `owns_or_admin` 与 `_load_owned_*` 校验,不受影响)。此为你 req4 的明确诉求。

**达人库**:顶部「我的达人 / 全部达人」切换 + 筛选(归属商务/等级/品类/状态)。
- 非归属达人:可见基础档案 + 合作概览;敏感字段(手机/地址/管理员备注)隐藏;操作列按钮全部替换为「申请建联」。
- 归属达人/管理员:照常可操作。

**建联流程**:
- 商务点「申请建联」→ 建 ConnectionRequest(pending)。
- 管理员新增「建联审核」tab:待审列表 + 通过/拒绝 + 审批历史,带待审数量徽标。
- **通过 → 达人归属转给申请商务**(owner_bd_id 改),写 OperationLog(owner_transferred);**旧商务立即失去操作权,仍可只读**(= 全库可见规则)。
- 拒绝/撤回按状态处理。

**接口**:
- `GET /api/influencers?scope=all|mine&q=&level=&owner_bd_id=&page=` → 全库/仅我的
- 非归属详情:敏感字段脱敏、无写接口
- `POST /api/connection-requests` `{influencer_id, reason}`(bd)
- `GET /api/connection-requests?status=`(admin)+ `GET /api/connection-requests/pending-count`
- `POST /api/connection-requests/{id}/review` `{approve, note}`(admin,通过即转移)
- `POST /api/connection-requests/{id}/withdraw`(申请人)

3. **需求2**:parse 重复返回 diff + 二次确认弹窗 + apply-update 逐字段落日志;Excel 重复行待处理。
4. **需求3**:MaterialPost/Asset + 发布弹框 + 管理端/达人端内容帖卡片。

## 验收红线(你的原话提炼)
- 达人详情不再以"第几轮"为核心,改为**产品大节点 + 时间轴**。
- 同一抖音号不产生两个达人;重复走差异确认。
- 每次重要操作可查到**操作人/时间/前后值/关联产品**。
- 非归属商务**只能看不能操作**;建联通过即转移,旧商务只读。
- 每份素材有清晰预览 + 说明文案;达人端与管理端读同一份数据。
- 刷新/重启/重登后信息仍从数据库恢复(全部落库)。
