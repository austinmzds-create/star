# 内部账号密码登录设计

## 目标

在现有统一登录页增加账号密码入口，同时保留手机号验证码登录：

- 管理员、商务可以使用账号密码登录。
- 管理员、商务、达人仍可使用手机号验证码登录。
- 达人不提供账号密码登录能力。
- 默认管理员测试凭证保持为 `admin / admin123`。

## 交互设计

登录卡片使用 Element Plus 标签页，提供“手机号登录”和“账号密码登录”两个入口，默认显示手机号登录。

手机号标签页沿用现有手机号、验证码、获取验证码、倒计时和登录流程。账号密码标签页显示账号、密码和登录按钮；密码输入框默认遮蔽并支持显示/隐藏，用户在账号或密码输入框按回车即可提交。

品牌区副标题改为同时描述两种登录方式。账号密码标签页明确提示“仅管理员和商务使用”，避免达人误以为需要账号密码。

两个标签页分别维护表单内容和提交中的 loading 状态，切换标签不会误用另一种登录方式的数据。

## 数据流与权限边界

手机号验证码登录继续调用 `POST /api/auth/sms/login`。成功后沿用现有身份分流：达人进入 `/h5`，管理员或商务进入 `/workbench`。

账号密码登录调用现有 `POST /api/auth/login`，请求体为：

```json
{
  "username": "admin",
  "password": "admin123"
}
```

该接口只查询内部 `User` 账号并签发 staff token，因此账号密码登录天然只适用于管理员和商务，不为达人增加密码入口。登录成功后写入现有的 `token` 和 `user` 本地存储键，并进入 `/workbench`。

本功能不修改后端鉴权模型、数据库结构或角色权限。

## 校验与错误处理

- 手机号登录继续校验 11 位手机号以及手机号、验证码非空。
- 账号密码登录在前端校验账号和密码均非空；缺失时给出明确提示，不发请求。
- 后端返回的错误优先显示 `response.data.detail`，网络或未知错误统一显示“登录失败”。
- 请求期间按钮显示 loading，并防止重复提交；无论成功或失败都恢复 loading。
- 停用账号和错误密码继续由现有后端分别返回对应错误，不在前端复制权限判断。

## 测试与验收

前端新增针对登录行为的自动化测试，至少覆盖：

1. 默认展示手机号登录，并可切换到账号密码登录。
2. 账号或密码为空时不调用接口并显示提示。
3. 账号密码提交到 `/api/auth/login`，请求字段正确。
4. staff 登录成功后保存 token 和 user，并导航到 `/workbench`。
5. 后端错误详情可见，提交结束后 loading 恢复。
6. 密码表单支持回车提交。

完成后运行前端测试和 `npm run build`，再用默认管理员 `admin / admin123` 做浏览器登录冒烟测试。手机号验证码原流程也需做一次回归检查。

## 非目标

- 不给达人创建用户名或密码。
- 不增加注册、忘记密码、重置密码或记住密码功能。
- 不改变默认管理员凭证的 seed 逻辑。
- 不修改现有 token 格式、路由守卫或角色权限。
