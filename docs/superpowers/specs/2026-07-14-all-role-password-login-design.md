# 全角色账号密码登录设计

## 目标

管理员、商务、达人都同时支持两种登录方式：

- 手机号 + 短信验证码。
- 账号/手机号 + 密码。

管理员保留现有 `admin / admin123`。商务和达人的默认账号是手机号，初始密码是手机号后 6 位。首次密码登录后暂不强制修改密码。

## 凭证规则

内部账号 `User` 继续支持现有 `username`，同时允许使用 `phone` 作为密码登录标识。达人不新增独立用户名字段，直接使用 `Influencer.phone` 作为密码登录标识。

默认密码只在账号尚无 `password_hash` 时生成：

```text
手机号：15095037973
账号：15095037973
初始密码：037973
```

密码只保存哈希，不保存明文。已经拥有密码哈希的管理员、商务或达人不会被启动补齐程序覆盖，因此管理员的 `admin123` 和未来用户自行修改的密码都能保留。

没有手机号的达人不生成密码登录资格。补齐手机号后，如果仍没有密码哈希，则自动生成手机号后 6 位的初始密码。

## 数据模型与兼容迁移

`Influencer` 增加可空的 `password_hash` 字段。`User` 已有该字段，无需新增列。

项目继续使用现有 `ensure_columns()` 兼容迁移机制，为旧数据库自动增加 `influencers.password_hash`，不要求测试环境手动执行 SQL。启动 seed 扫描所有有手机号且密码为空的内部账号和达人，生成默认密码哈希。

新建或更新 `User`、`Influencer` 时，在账号具备手机号且密码仍为空的情况下自动生成默认密码。修改手机号不会覆盖已有密码。

## 登录数据流

现有 `POST /api/auth/login` 请求结构保持不变：

```json
{
  "username": "15095037973",
  "password": "037973"
}
```

后端按以下顺序解析身份：

1. 在内部账号中匹配 `User.username == username` 或 `User.phone == username`。
2. 若命中内部账号，验证密码和 `is_active`，成功后签发 staff token。
3. 若未命中内部账号，再以 `Influencer.phone == username` 查找达人。
4. 验证达人密码和 `archived` 状态，成功后签发 influencer token。
5. 均未命中或密码错误时统一返回 401“账号或密码错误”。

手机号同时存在于内部账号与达人时优先识别为内部账号，与现有短信登录角色优先级保持一致。重复达人手机号沿用现有短信登录行为，选择数据库查询得到的第一条达人记录；本功能不自动合并达人数据。

密码登录成功响应继续使用现有结构：staff 返回 `kind: "staff"`，达人返回 `kind: "influencer"`。

## 前端行为

登录页保留“手机号登录 / 账号密码登录”双标签。密码标签的账号输入框提示改为“账号或手机号”，说明改为“管理员、商务、达人均可使用”。

密码登录成功后使用与短信登录相同的统一会话处理：

- 管理员、商务保存 staff token，进入 `/workbench`。
- 达人保存 influencer token 和 `h5_token`，进入 `/h5`。

本地测试角色切换器继续使用真实角色 token，不受本功能影响。

## 状态与错误处理

- 内部账号停用时返回 403“账号已停用”。
- 达人 `archived == true` 时返回 403“账号已停用”。
- 账号不存在、无密码或密码错误统一返回 401“账号或密码错误”。
- 没有手机号的达人不能通过密码登录，仍可在补齐手机号后获得初始密码。
- 密码登录接口不返回密码、密码哈希或初始密码提示。

## 测试与验收

后端自动化测试覆盖：

1. 管理员继续使用 `admin / admin123` 登录。
2. 商务使用手机号和后 6 位密码登录并获得 staff token。
3. 达人使用手机号和后 6 位密码登录并获得 influencer token。
4. 错误密码返回统一 401。
5. 停用商务和归档达人返回 403。
6. 无手机号账号不生成默认密码。
7. 已有密码哈希不会被默认密码补齐覆盖。
8. 补齐手机号后为空的密码哈希会自动生成。
9. 内部账号与达人手机号冲突时优先返回 staff 身份。

前端自动化测试覆盖：

1. 密码表单展示“账号或手机号”。
2. staff 密码登录进入 `/workbench`。
3. 达人密码登录保存 `token`、`h5_token` 和用户信息，进入 `/h5`。
4. 登录失败展示后端错误且恢复按钮状态。

浏览器验收分别使用管理员、商务和“二宝妈妈😇”完成密码登录，确认角色、菜单和跳转正确，同时回归三种角色的短信验证码登录。

## 非目标

- 本轮不实现首次登录强制改密。
- 本轮不实现忘记密码、用户自助修改密码或管理员重置密码页面。
- 本轮不自动合并重复手机号的达人记录。
- 本轮不改变 token 格式、达人授权规则或内部角色权限。
