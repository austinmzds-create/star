# 迭代 v0.4:可用性打磨 + 三角色权限 + UI 升级

> 来源:需求方 2026-07-12 体验反馈(9 条具体问题 + 整体方向)
> 原则:面向**非技术的商务/管理员**,界面清爽高级(不像 OA)、指示清晰、信息补全、详情用弹框/抽屉承载。
> 状态:**规划中,待确认关键决策后动手**

## 0. 整体方向(贯穿所有模块)
- **三角色**:达人 / 商务 / 管理员。普通手机号注册即「达人」,只能看到被授权的内容;管理员可把手机号设为「商务」;商务权限暂=管理员。
- **数据隔离(安全红线)**:达人端严格只见授权内容,绝不能看到他人手机号/地址/真名、未授权产品、内部管理数据。后端逐接口按角色校验。
- **UI 基调**:卡片式布局、充足留白、柔和高级配色、圆角、图标引导;列表信息补全;详情/操作用弹框(Dialog)或抽屉(Drawer)承载;空状态/加载/成功提示对非技术用户友好。
- **公共组件**:达人选择器(模糊搜索→自动填 id+姓名)、时间格式化、上传组件(多图)、角色守卫。

## 1. 身份与权限体系(架构级,最先定)
**现状**:内部端(管理员/商务)用账号密码登录;达人端用手机验证码。两套割裂。
**目标**(按反馈#3):
- 统一「手机号 = 身份」。手机号登录 → 角色由后台决定:管理员设过的手机 = 商务/管理员,否则 = 达人。
- 管理员在「商务管理」用手机号添加商务 → 该手机登录即得商务身份(反馈#3)。
- 商务权限暂时 = 管理员(用户明确:先一致,细分以后再说)。
- 待办:
  - [ ] 统一身份模型(User 增加 role=admin/bd/influencer + phone 唯一;或 Influencer 与 User 打通)
  - [ ] 登录方式决策(见开放问题①)
  - [ ] 后端所有接口加角色守卫;达人端接口只返回授权数据
  - [ ] 前端按角色渲染菜单/按钮/页面

## 2. 达人库

- [ ] **列表字段补全**(反馈#2):昵称 / 抖音号 / 粉丝 / GMV / 等级 / 佣金 / 标签 / 归属商务 / 轮次 —— 全部列出,空值显示占位("—")。
- [ ] **详情页「寄样记录」面板**(反馈#5):在达人详情左侧承载该达人的寄样历史 —— 寄了几次、每次什么时间、哪个品、物流状态/到哪了、是否签收。数据来自寄样管理,但在达人视角聚合直观展示。
- [ ] **时间格式化**(反馈#4):`2026-07-12T00:11:01.190283` → `2026-07-12 00:11`(全局统一)。

- [ ] 敏感字段(手机/地址/真名)在达人端一律不可见他人。
- [ ] 前端路由守卫 + 后端强校验双保险。

## 竞品 UI 参考(高级清爽方向)
- **蝉圈圈 / MCN 达人 CRM**:卡片列表 + 抽屉详情 + 选人模糊搜索,可借鉴信息密度与详情承载方式。
- **现代 SaaS 清爽风**(Linear / Notion 式):大留白、清晰层级、克制配色、圆角卡片 —— 对标"不像 OA、高级"的诉求。
- 详情一律弹框/抽屉,列表只放关键列 + 点击看全貌。

## 已定决策(2026-07-12)
1. **登录方式**:✅ 统一手机验证码(管理员/商务/达人都手机登录,角色后台定)。管理员首账号用配置白名单手机引导登录。
2. **商务添加**:✅ 管理员填手机号**直接生效**,商务首次登录即得权限。
3. **卡审关联达人**:选填(通用规范可不关联)。
4. **改造节奏**:✅ 先公共件 + 设计基调,再逐模块。

## 实施顺序
- **P1a 身份鉴权统一**(后端):统一手机验证码登录 → 角色解析(staff/influencer);商务管理(手机号直接加);后端逐接口角色守卫;管理员白名单手机引导。
- **P1b 公共件 + 设计基调**(前端):统一主题(清爽高级)、达人选择器(模糊搜索)、时间格式化 util、多图上传组件、登录页改手机验证码、角色路由守卫。
- **P2 达人库**:录入双模式(粘贴/手动)、列表补全字段、详情寄样记录面板、时间格式化落地。
- **P3 产品中心**:列表补全、Tab 式详情大框(查看+直接添加)、授权达人模糊搜索。
- **P4 卡审知识库**:表单增强(视频链接/原视频、多截图、关联达人)。
