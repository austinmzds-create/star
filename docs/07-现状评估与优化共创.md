# 07 · 现状评估与优化共创（当前阶段）

> 目标:从整体看当前项目——各模块该做的优化、哪些地方串联更自然、更符合使用、操作便捷、数据清晰、UI 调整、以及问题点/红线。
> 基于全量前后端代码复核(含 Codex 的千川/寄样重构/密码登录 + 本轮达人端 tab 重构)。

## 一、总体判断

核心业务链已通(建档→寄样→物流→视频审核→投流→出单),达人端刚重构为 tab + 双布局 + 卡审可见,安全/CRUD 已加固一轮。**现阶段主要短板集中在 5 类**:
1. **串联** —— 跨模块/跨记录几乎没有"点名字跳详情",待办/徽标不精确跳转(日常最高频摩擦)。
2. **千川** —— 新增的绑定 UI 把工程态直接暴露给运营;且千川绑定与原「投流」状态机重复、互不连通。
3. **数据展示** —— 金额/数字格式不统一,多处缺加载/空态,看板偏 OA 感。
4. **粗糙点** —— OSS key 等技术字段直接让运营填、死代码、错误被吞。
5. **生产红线** —— dev 切换身份 + 默认 admin/admin123 在 DEBUG 未关时可达;快递回调无签名;千川 token 明文。

## 二、串联更自然(跨模块/跨端)—— 高频、低风险、优先

| # | 现状 | 优化 |
|---|---|---|
| 1 | 工作台待办"待发货/待处理投流/待审视频"都落到页面**默认 tab**,要再点一次 | 待办带 `?tab=/?status=` 精确跳到对应子 tab |
| 2 | 侧栏"寄样/视频"徽标各自**合并两种状态**成一个数字 | 拆成两个,或进入前就能区分哪种紧急 |

## 三、逐模块优化

**工作台 Workbench**:待办精确跳转;加加载骨架(现在请求回来前整页空白);GMV 与看板格式统一。

**达人库 Influencers**:补"按归属商务/标签/来源"筛选(列都显示了却不能筛);粉丝/GMV 数字格式化(现在裸数字挤在 80px);表格加 loading/empty;粘贴录入与 Excel 导入两个入口略冗余,可合并为一个"+录入"。

**达人详情 InfluencerDetail**(全站最佳交互模板):但有**两个编辑入口**——"编辑档案"弹窗(改昵称/抖音/地址)与内联"定级"表单(改等级/佣金/归属),运营分不清哪个改什么,建议合并或明确分区;左列过长右列过短,布局不平衡;寄样/视频/投流行的产品名/视频应可跳转;投流 tab 可操作化。

**寄样 Samples**:达人/产品可跳转;发货弹窗里显示达人已存地址便于核对;`products` 只在挂载时拉一次,会话中新建的产品不出现,改为打开即刷新;"拒绝原因"列在非拒绝 tab 也占宽,浪费。

**视频与投流 Videos**:双层 tab(主 tab + 子状态 tab)偏重;**"失败截图 OSS key"让运营填**——改成 MultiUpload 上传;`blockVideo` 用 `.then()` 无 catch,标记卡审失败会**静默无反应**;`vLoading/pLoading` 声明了但没绑 `v-loading`(死引用);发起投流后跳转。

**产品中心 Products(千川是重灾区)**:
- 列表"千川"列状态 `unconfigured/draft/configured`,但抽屉里让运营**手动选** `bind_status`——这种状态应**派生**而非手选;
- 千川头部堆三个术语标签(未绑定店铺/待配置开放平台/合作同步待接入)+ 一条 missing_config 警告——正是要避免的工程师视角;
- **三条重叠录入路径**(手填店铺/广告主/商品ID vs 选授权店铺自动填 vs 从店铺同步),认知负担高,收敛为一条主路径 + "高级";
- N+1:列表每行都查授权数 + 千川状态;`refreshDetail` 死代码;抽屉内每次操作都全量 `load()` 重拉列表。

**卡审 BlockRecords**:关联达人可跳转;表格加 loading/空态;创建时"违规类型/文案"都可空,会产生近空记录,加校验。

**看板 Dashboard**:加 loading/空态;金额加 ¥+千分位(与工作台统一);`by-tier` 忽略 `days` 筛选(改范围只更新商务表不更新档位卡)——**bug**;商务行可下钻;整体用 stat-tile 样式去 OA 感;`by-product` 后端缺产品名。

**配置 Settings**:快照提示("只影响新数据")前置到显眼处;"商务=管理员"这条治理策略需产品拍板(现在除 /dashboard /settings 外商务几乎等同管理员)。

**登录 Login**:logo 渐变 `#4f6ef7→#7a5cf6` 与全站主色 `#6b5cf6` 不一致——运营第一眼就是另一种紫;背景与全局 body 背景不一致;生产登录竟走名为 `test-role-session` 的模块 + 残留 `data-testid`,建议改名/剥离。

**达人端 H5**(本轮已重构):tab/双布局/卡审可见已完成。剩余小项:产品资料中心/拍摄前必读两个详情页未跟随手机/电脑切换;`TestRoleSwitcher` dev 覆盖层在 dev 下压住底部 tab(生产 build 不出现,不影响线上)。

## 四、数据清晰度(横切)

- **金额/数字格式不统一**:GMV 在工作台是 `¥+千分位`,看板是裸整数,达人库粉丝/GMV 裸数字 → 抽一个共享 formatter,全站统一。
- 空态/加载态多处缺失(看板、达人库、卡审表)→ 统一补 `v-loading`+`el-empty`。
- 徽标合并两态 → 拆分或进入前可辨。
- `dashboard.by-product` 缺产品名,前端无法直接渲染下钻。

## 五、UI 样式

- 登录品牌色/背景与全局统一(主色 `#6b5cf6`)。
- 看板去 OA 感,改 stat-tile(参考工作台/达人详情已有样式)。
- 侧栏 logo 品牌化(用登录页那个紫方块)+ 徽标右对齐(现在挤在文字后)。
- 千川表单术语标签收敛;抽屉内各 tab 的 label 宽度不一(88/110/inline)统一。
- 达人库 `material_count/granted_count` 加"个/人"单位与零态样式。

## 六、问题点 / 红线(要修的 bug 与风险)

**安全(高)**
1. `/api/auth/dev-switch`(免鉴权换任意角色 token)只按 `settings.debug` 门控,而 `debug` **默认 True**、`.env.example` 也是 `DEBUG=true`;加之默认 `admin/admin123` 无条件种子。生产忘设 `DEBUG=false` = 任何人可拿管理员 token。→ 启动强制 `debug=False`(与 SECRET_KEY 校验耦合)、移除/改造默认 admin、dev-switch 加显式独立开关。
2. 快递100 回调 `kd100_callback` 无签名校验,仅凭 `tracking_no` 单键匹配即可把单改成"已签收"——可伪造。→ 加签名校验 + 多单号消歧。
3. 千川 access/refresh token **明文存库**,无刷新流程,`advertiser_ids` 只取第一个(多广告主丢失)。

**正确性(中)**
4. 达人库 `tag` 筛选在**分页之后**对当前页过滤 → `total` 错、跨页命中看不到。
5. 寄样列表分页在 **Python 内存里切片**(先全量载入再切),规模上有隐患;建单绑定"最新合作轮次"未过滤 `status`,已结束的轮次也能开新单。
6. 千川绑定状态机与原 `Promotion` 投流状态机**重复且不连通**(一个按 product×influencer,一个按 video_task),"投流(千川)"无法端到端串起——需定**单一真相**。
7. `sync_cooperation` 是**投机占位**(无真实千川接口,依赖运营自填 URL + 猜返回字段),"一键同步"对真实 API 会失败——需标注实验或实现真接口。

**性能(中)**
8. 读接口在**循环里同步调外部物流 HTTP**(`h5.me`/`my_materials`/`influencer.activity`,每单一次 15s 超时的 kd100 查询并各自 commit)→ 达人样品一多就慢/易超时。改后台/按需刷新。
9. `list_products` 每行 N+1(授权数 + 千川状态)。

**健壮/运维(低-中)**
10. 死字段/未实现:`auto_audit_type`(含"18:30 自动通过")从未被读取执行;爆款链接自动转存、视频转存 OSS、蝉妈妈自动 GMV 均为 TODO——UI 上别给出"已支持"的错觉。
11. 催拍 scheduler 先睡 24h 再首扫、重启重置计时,频繁部署会漂移/不触发。
12. 迁移仍是 `create_all + ensure_columns` 无 Alembic;新加的 `UniqueConstraint` 只因是新表才生效(加到已存在表会被静默跳过)。

## 七、建议分批(供拍板)

- **批次 A(串联 + 便捷,高频低风险)**:全站"点名字→详情"deep-link + 工作台/徽标精确跳转 + OSS key 改上传 + 补 loading/空态 + 金额统一格式。**体感提升最大。**
- **批次 B(千川收口)**:重做千川绑定 UI(隐藏工程态、状态派生、录入路径收敛)+ 定"千川绑定 vs 投流状态机"单一真相。
- **批次 C(生产安全红线)**:dev-switch/默认 admin 硬门 + 快递回调签名 + 千川 token 加密。
- **批次 D(性能/健壮)**:分页统一 + N+1 + 读接口物流异步化 + tag 筛选修复 + Alembic。
